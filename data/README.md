# Source ledgers

[中文说明](#中文说明)

This directory makes discovery and screening inspectable. It does not claim that every resource is high quality or that every experiment has been independently reproduced.

Every file here belongs to one of the five groups below. Change hand-maintained files in a reviewed commit. Rebuild generated files with the named script instead of editing them. Leave frozen records unchanged: they are the evidence for a decision that has already been published.

## Ledgers

| File | Maintained by | Role |
| --- | --- | --- |
| `ecosystem-sources.jsonl` | The source scan (`scripts/refresh_sources.py`) or a full rebuild (`scripts/collect_ecosystem.py`); reviewed additions by hand | Direct and adjacent ecosystem sources, retrieved page evidence, provenance, and content hashes. |
| `research-sources.jsonl` | The source scan or a full rebuild (`scripts/collect_research.py`); primary-abstract imports by hand | Direct studies and background research, with primary-page or scholarly-API abstract provenance and explicit screening scope. |
| `ecosystem-sources.excluded.jsonl` | `scripts/collect_ecosystem.py`; the source scan removes any row it accepts | Candidates excluded by the ecosystem screen. |
| `source-curation.json` | By hand | Maintainer-reviewed exclusions and display-only metadata corrections, with primary-source evidence. |

Verification levels are `editorial_reviewed`, `content_screened`, `abstract_checked`, and `metadata_only`. The first denotes targeted editorial inspection; the next two record source-page or original-abstract checks at the scope stated in each record. Metadata-only entries and failed fetches do not count as checked content. Abstracts supplied through an index API do not imply that the original publisher page was fetched.

Primary arXiv abstract imports use `abstract_provider: arxiv_primary_abstract_page`, a same-paper fixed `reviewed_version_url`, its matching `reviewed_version`, a primary-page SHA-256, and `canonical_page_separately_fetched: true`. Keep initial submission in `published_at` / `first_submitted` and the inspected revision date in `reviewed_version_date`. The validator rejects aliases that would bypass the scanner's version protection, conflicting URL identities and missing primary-page evidence. Index-supplied abstracts retain their own provider provenance; they are not required to claim a separately fetched primary page.

Read [the audit methodology](../docs/source-audit.md) and [the maintenance guide](../docs/maintenance.md).

## Generated files

Do not edit these by hand; run the script and commit its output.

| File | Generated by | Role |
| --- | --- | --- |
| `source-counts.json` | `scripts/build_source_index.py` | Counts after cross-ledger URL, content-hash, and paper-title deduplication. The same run regenerates `site/data/source-index.json` and `site/data/source-badge.json`. |
| `scan-latest.json` | `scripts/refresh_sources.py` | Report of the most recent source scan: added and changed URLs, error counts and bounded error examples. The scan PR proposes it together with the ledgers. |
| `expansion-progress-2026-10-16.json` | `scripts/build_expansion_report.py` | The reviewed-expansion count against the frozen baseline, with every accepted addition. The same run regenerates [the expansion directory](../docs/expansion-2026-10-16.md). The site build renders the discoveries pages from it and publishes a copy as `site/data/expansion-progress.json`. |

Regenerate the browser index and counts with:

```sh
python3 scripts/build_source_index.py
```

## 中文说明

本目录公开来源发现与筛查过程，便于检查；它不表示每项资源质量都高，也不表示每个实验都已被独立复现。

文件分为五类：

- **来源台账**：`ecosystem-sources.jsonl`（生态来源及其抓取证据、出处和内容哈希）、`research-sources.jsonl`（直接研究与背景研究，含原始页面或学术 API 摘要出处）、`ecosystem-sources.excluded.jsonl`（生态筛查排除的候选）和 `source-curation.json`（人工审阅的排除项与仅影响显示的元数据更正）。前三份由来源扫描 `scripts/refresh_sources.py` 或全量收集脚本 `scripts/collect_ecosystem.py`、`scripts/collect_research.py` 写入，经审阅的新增行和原始摘要导入可人工添加；扫描接受某个来源时会从排除台账中删除该行。`source-curation.json` 只能人工修改。
- **生成文件**：不要手工编辑，应重新运行脚本并提交结果。`source-counts.json` 由 `scripts/build_source_index.py` 生成，同时更新 `site/data/source-index.json` 与 `site/data/source-badge.json`；`scan-latest.json` 是最近一次扫描的报告，由 `scripts/refresh_sources.py` 写入；`expansion-progress-2026-10-16.json` 由 `scripts/build_expansion_report.py` 生成，同时更新[扩展目录](../docs/expansion-2026-10-16.md)，网站据此生成新增来源页面并发布为 `site/data/expansion-progress.json`。
- **网站构建输入**：人工编辑后运行 `node scripts/build_site.mjs`，并在同一改动中提交重新生成的 `site/` 文件。`search-guide.json` 是双语指南，`research-topics.json` 是双语研究专题（每个专题的 `guide_section` 必须对应指南中的某一节），`discovery-translations.zh-CN.json` 以完整英文简介为键保存中文简介，`scripts/build_source_index.py` 也会读取它。
- **资源扩展记录**：`expansion-baseline-2026-10-16.json` 与 `expansion-baseline-supplement-2026-10-16.json` 冻结扩展前的基线提交及已知 URL、证据哈希和论文题名，补充文件只追加排除项；`expansion-intake-2026-10-16.json` 在每次审阅发布时人工更新，列出已接受的公开 URL。扩展以基线提交为起点计算，目标为 301 项新来源，当前总数见 `expansion-progress-2026-10-16.json` 的 `accepted_new_sources`；只有新的、不重复且有证据的条目才计入，不代表全文精读或运行模型。
- **审阅与审计记录**：其余带日期的 JSON 文件各自冻结一次审阅或核查的抓取内容、哈希、结论和限制，并由上表“Linked from”列中的页面链接。新增记录应与其支持的改动在同一提交中加入，并从相应页面链接。

证据等级为编辑审阅（`editorial_reviewed`）、内容筛查（`content_screened`）、摘要核查（`abstract_checked`）和仅元数据（`metadata_only`）。编辑审阅表示有针对性的编辑检查；内容筛查和摘要核查按各记录写明的范围记录原始页面或原始摘要的检查。仅元数据的条目和抓取失败不计入已检查内容；通过索引 API 获得的摘要不表示已抓取出版方原始页面。

arXiv 原始摘要导入使用 `abstract_provider: arxiv_primary_abstract_page`，并记录同一论文的固定版本 `reviewed_version_url`、对应的 `reviewed_version`、原始页面 SHA-256 和 `canonical_page_separately_fetched: true`。首次提交日期写在 `published_at` / `first_submitted`，实际查看的修订版日期写在 `reviewed_version_date`。校验器拒绝会绕过扫描版本保护的别名、相互冲突的 URL 身份以及缺少原始页面证据的记录；索引提供的摘要保留各自的出处，不必声称单独抓取过原始页面。

台账只保留最少的证据和公开书目信息，不保存全文或模型权重。第三方摘录和链接资源保留其原有权利与许可；本项目的 MIT 许可只适用于项目自身的代码和文字。
