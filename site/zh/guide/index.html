Jev 是什么？

Jev 是 TypeSafe 的 System One 模型。请求提供状态和类型化问题，响应返回边界明确的答案与概率，供应用代码完成分类、路由或复核。 TypeSafe 官方介绍

TypeSafe 将其训练方法称为 Reinforcement Learning for Calibrated Decisions，简称 RLCD。这是厂商对方法的描述，并不足以重建 Jev 的架构或训练过程。 TypeSafe 发布文章

类型化决策与 LLM 的结构化输出有什么区别？

类型化决策接口在推理前规定允许的候选答案。生成式 LLM 也能通过约束解码产生结构化输出。仅凭接口形式，不能判断哪个模型更准确、校准更好或效率更高。 XGrammar 论文

格式合法的答案仍可能选错。应区分 schema 合法性与语义正确性，并在自己的任务上测试模糊指令、对抗输入和选项顺序变化。 Jev 1.13 已知局限

Choice、Score 和 Noul 分别返回什么？

Choice 从调用方定义的候选项中选择，返回所选项、所有候选项的概率及置信度，适合有限类别或动作选择。 Choice 文档

Score 对文字描述的有序等级进行评估，返回等级编号的概率加权均值、概率分布与置信度；它不是从输入中抽取的精确测量值。 Score 文档

Noul 返回是非命题为真的概率，没有独立的 confidence 字段。接近中间的数值表示不确定性，不一定表示该属性处于中等程度。 Noul 文档

应区分有序等级的使用分布、Score 均值、返回的置信度与概率校准。该量表研究 v2 在所测模型与数据集上报告：最终选择集中，即使平均候选概率分布较宽；细化量表加剧压缩，提高准确率也未必恢复等级使用。若系统最终选择一个等级，可将其频率与参考标签频率比较，而非假设各等级应均匀出现。这是额外诊断，不是校准检验。上述研究发现来自作者摘要，未经本项目复现，也不能据此断言 Jev 的 Score API 存在同样问题。 有序量表使用偏差研究 v2

置信度就是答案正确的概率吗？

不能直接等同。TypeSafe 根据返回的分布计算置信度。例如，Choice 有四个选项，最高概率为 0.70 时，confidence 为 0.60；Score 使用不同公式。校准关注多次预测中的实际发生频率，不保证某个答案一定正确。 置信度文档

怎样评估决策质量与概率校准？

分别评估预测质量与概率质量。除准确率或适合任务的误差指标外，还应查看可靠性图，以及 Brier score、log loss 等适当评分规则。使用独立测试数据，不在最终测试集上调节阈值。 校准研究 · 适当评分规则

对于拒答或升级处理，应报告覆盖率和已接纳案例中的错误，并验证后备模型能否纠正错误。固定模型版本与提示词，单独测量端到端延迟、失败和成本。这是评测方案，不是本项目对 Jev 已取得的实验结果。 SelectiveNet · 模型版本

AudioJev 将顺序校准定义为等价候选重排下的概率稳定性。比较重排分布前，按候选含义对齐，再分别评估准确率与概率是否符合实际正确率。发布模型卡描述的是一个种子、原始顺序得分，并披露音频来源重叠；这些结果不能替代论文三种子平均值。 AudioJev 发布范围

校准良好的评判模型仍可能有偏差吗？

应区分概率校准、与人类排序的一致性及判断稳定性。CALM 研究发现，所测类型化评判模型即使校准或一致性较好，仍可能受位置和改写影响。研究沿用基准标签与改写，清晰度等非目标因素的变化限制了对语气影响的因果解释。 类型化模型评判偏差研究 v1

PRISM 用反事实强调探针和人类标签，学习对整体评判分数的校正。其在 SummEval 与 HANNA 上报告的排序一致性提升，与概率是否符合实际正确频率是不同目标。不要求逐项评分标准并不等于不需要标签，额外探针也有成本。这一 PRISM 方法与名称相近的 Prism-1 选项读出架构是不同工作。 PRISM 原始摘要 v1 · PRISM 局限 v1 · Prism-1 v1

我们建议分列报告排序一致性、概率可靠性和扰动敏感性；先核查所谓保留含义的改写是否仍应使用原标签，为学习到的校正保留独立测试分组，并把探针调用计入评估预算。重复相同请求可以估计变异性，但不能证明判断正确。

怎样比较决策模型、已训练分类器与语言模型？

决策门控基准 v2 报告，在有标签基准中，微调后的 DeBERTa-v3-large 除一项外均取得最高观察准确率；这一结果以可取得任务标签为条件。实际比较时，应分开报告有无任务训练标签的设置，并记录数据接触、开发/测试划分、输出格式与失败，再比较准确率、选择性覆盖或成本。 决策门控基准 v2

LLM-as-Jev v3 研究冻结 Qwen 的读出、带 KL 锚定的可选微调及限预算推理。为区分这些影响，我们建议保留同骨干的冻结基线，明确选项集合和数据划分，并单独记录推理预算。所报比较针对两个 Qwen 骨干及一个独立框架，不能据此揭示托管 Jev 的训练或架构。 LLM-as-Jev v3

HakemBench v1 明确说明，多数土耳其语参考标签由 AI 生成、未经人工核验；实验室自身模型在被标记的任务上还受过先前测试结果的影响。应报告标签来源、既往测试集使用情况和逐任务指标分量，将翻译探查与独立的语言验证分开。这些是建议的比较检查，本资源库未复现上述研究。 HakemBench v1

问题分组属于推理协议。Perplexity Decider v1.2 允许同一请求中的问题相互关注，而快速路径会隔离不同请求；模型卡报告，将相关属性放在一起可能有帮助，将相互竞争的检索候选放在一起则可能降低表现。相对地，tasksource-decider-nano 描述了共享状态但隔离选项的树形注意力。报告分数时应同时记录分组规则，多问题 API 不代表答案相互独立。 Perplexity v1.2：问题分组 · tasksource：树形注意力

快速基准能证明哪些部署能力？

先区分证据来自实测设备、仿真、回放还是运行中的服务。HVAC 研究使用公开设备测量，但故障日较少、诊断依赖特征，限制了迁移；HydroJEV 使用仿真窗口，事件和数字孪生来自同一水力模型。非劣效区间与多重比较校正后的检验不同，一个迁移端点没有通过校正检验。两篇研究均不能确立普遍的现场表现保证。 HVAC 研究局限 v1 · HydroJEV 仿真局限 v1 · 迁移端点

成功请求耗时应与观测、特征构造、重试等待、排队及后续执行分开。无线研究不计主动间隔和重试等待，并引用另一项编排研究说明：解释更快不一定改善服务完成结果。流量分类研究没有计时数据包观测或特征提取。我们建议在同一负载下记录所有阶段、超期与最终效用，再比较部署表现。 无线计时边界 v1 · 外部编排证据 · 流量分类范围 v1

输出合法性和改写稳定性不足以检验控制行为。5G 测试床研究固定状态与选项，只改变问题，发现一个微调检查点仍返回训练时的答案。其 RAN 平面未闭合、没有真实无线电，风险结论也依赖校准协议。应同时测试理应改变的动作与应保持的不变性，并评估完整控制器，不能从类型化响应推断可靠性。 改变问题的对照 v1 · 测试床与认证局限

置信度门控可以直接迁移到其他语言或领域吗？

将置信度门控用于新的语言或领域前，应构建目标测试集，明确标签定义与标注来源；翻译标签或模型生成的标签不等于独立人工验证。比较沿用原门控与仅在单独目标领域验证集上调节阈值的方案，分别报告各组的接纳样本错误率和覆盖率，并检查经独立核验、保持答案不变的上下文补充是否造成高置信错误。

社会科学标注论文使用基准标签，报告了随任务变化的置信度失效；JevOut 的人工检查仅覆盖成功扰动中的抽样子集。两篇摘要均未确立多语言迁移结论。分语言标签检查与阈值迁移比较是本项目建议的流程，并非已复现结果或总体保证。 社会科学标注评测 v2 · JevOut v2

实现文档还给出了迁移限制。FRIDA-Decisions 建议使用较短的俄英状态，并使用俄语指令后缀；Jev-AR 说明其合成阿拉伯语训练数据未经母语者验证，按内置路由拟合的置信度在自定义列表上只能近似使用。这些是文档中的适用条件，不是门控可以迁移的证据；本项目未运行这两个实现。 FRIDA-Decisions 的限制 · Jev-AR 的限制

印尼地方语言研究给出一个具体区别：预期校准误差未增加，但错误排序能力变差。翻译比较使用人类印尼语翻译，分类器比较受标签预算影响，级联则取决于后备模型和分流比例。迁移阈值前应分别评估这些因素。预注册与材料发布仍属作者报告，本项目没有审计逐项预测。 印尼地方语言迁移研究 v1

候选覆盖基准在相同标签预算下比较冻结的源阈值与目标任务本地阈值。即使满足源任务校准约束，阈值在换任务后仍可能失效。应区分人为移除、自然检索遗漏与范围外输入，后两者各用自己的分母。校准与拒答专题将这些测试与接口一致性、随机升级对照和级联总成本联系起来。 候选覆盖与策略迁移 v2 · 校准与拒答研究专题

语言变化和任务变化需要分开。立场研究比较英语单文本与中文对话，审核研究则改变规则、带标签先例和答案菜单。这些是有价值的任务观察，却不是单独识别语言迁移的实验。语言任务专题还区分额外提问的成本与质量，以及冻结骨干与监督校准。 立场研究 v1 · 语言任务评测专题

兜底选项和置信度门控是一回事吗？

名为 Other 或 Defer 的兜底选项，是模型需要按定义选出的答案。置信度门控则由应用代码决定是否执行已有答案，或将任务升级处理。TypeSafe 的路由示例展示后者。比较可靠性前，应明确测试的是哪一种接口。 兜底定义 v1 · TypeSafe 置信度路由

成对兜底鲁棒性测试固定输入与选项位置，将正确输出从常规选项改为兜底项，并比较含义等价的兜底定义。在所测开放模型中，正确识别类别，甚至直接给出正确类别，都不保证正确完成输出重分配。这是文本数据上的受控诊断，尚未确立生产修复方法。 成对重分配与定义测试 v1 · 研究局限 v1

我们建议分别报告常规选择准确率、正确兜底选择、不必要兜底及等价定义间的分歧。应用层置信度门控应在留出样本上另行测试，成本应计入升级调用。顺序稳定与选项间概率比稳定是另外的性质：Prism-1 明确指出，“以上皆非”规则并不适合独立选项评分。 Prism-1 的范围与限制 v1

怎样测试模型对表格与引用证据的决策？

分别评估输出结构合法性、保持内容不变时的稳定性，以及相对于参考标签的语义正确性。对表格，将原输入与不同版式或行列重排配对，但仅在含义不变时进行；保持数值、关系和算术不变，再比较选项与概率分布。答案稳定仍可能错误；不能仅凭低置信度判定错误。 表格决策预印本 v1

对引用证据，固定待验证的主张和算术，将引文替换为数值相同、却对应不同财务项目的段落。保留等价有效证据作为正对照，分别统计误接纳错配证据与误拒绝有效支持的情况。检查配对差异，不把每次答案变化都当作错误。这些构造案例只是诊断探针，不能据此估计真实流量中的错误率。 同数值引用替换预印本 v1

怎样测试工具参数核验与选项通道风险？

分别检查 schema 合法性、引用证据是否支持提议参数值，以及该值是否能由请求、历史和 schema 默认值推导出来。测试没有显式参考的正确默认值或推导值，也测试配有可见参考的错误值；参考存在不等于推导正确。若模型根据完整历史生成参考，应对参考生成器隐藏候选值，并核查输出；生成的参考不是真值。 工具参数核验预印本 v1

明确谁能改动请求文本、工具输出、选项名称和政策定义，分别测试威胁模型允许攻击者控制的通道，包括错误决策时的置信度。所引防护实验针对开放权重的类型化决策模型，并未证明托管 Jev 已被攻破。这是建议的评估流程，不是已复现结果。 选项通道防护预印本 v1

区分标签敏感性的现象与成因。Labels Override Definitions 在所查开放实现中固定权重，改变标签／定义渲染后，偏置也随之改变。对可检查的系统，应记录实际渲染请求，并比较冲突标签、只含定义与中性标签变体。这是建议的诊断，既不能据此确定托管 Jev 的内部机制，也不构成通用防御。 Labels Override Definitions v1

攻击成功率究竟衡量什么？

在称攻击成功前，先定义所测结果与分母。概率偏移、动作改变、攻击目标被选中和后续危害是不同结果。Same Attack 只在各裁判未攻击时已标记的恶意案例中计算攻击后变为放行（pass）的比例。它另行计算的 Jev 门控绕过要求动作放宽且严重程度 Score 的置信度 ≥0.7；改为复核（review）也可能满足条件，低于阈值的放行则不满足置信度条件。 Same Attack 指标定义 v1

用同一决策规则，将攻击与匹配的原样请求比较。JevAdvBench 区分 Score 最可能等级变化和期望分数变化。自适应搜索应将优化调用与验证分开：Decision Hijacking 冻结候选后另发五次新调用，至少三次选中目标才算案例级成功。这种有限重复规则不保证以后的调用也成功。 JevAdvBench 类型化指标 v1 · Decision Hijacking 验证协议 v1

Decision Hijacking 的一个条件在 2,550 次调用中选中目标 51 次，但多数成功案例为 510 个中的 11 个，两个分母回答不同问题。Same Attack 报告 Jev 重复内容审核调用的原始严重程度评分有 75% 变化，路由动作却仅 1%。这些是作者报告的例子，不是本项目复现结果或排名。应另查编辑是否保持答案、是否送达；token 数相同本身不证明编辑被移除。 调用级与案例级计数 v1 · 数值与路由波动 v1 · 送达推断限制 v1

官方 SDK 和独立模型就是发布的 Jev 权重吗？

官方 SDK 是 TypeSafe 托管 API 的客户端，并非 Jev 检查点。Laya 等独立项目发布的是各自的模型材料。问题类型相似或 API 兼容，不证明架构、行为或准确率相同。 官方 Python SDK · Laya 模型卡

应分别检查每个版本的模型卡与许可。例如，Bespoke Nimble 9B v3 声明采用 CC BY-NC 4.0，限制商业用途。不能把所有可公开下载的模型材料都称为不受限制的开源模型。 Bespoke Nimble v3 模型卡

API 形状不能决定实际推理路径。Span-02 文档包含专用运行库和可选生成推理，榜单配置也不同于普通服务；Lychee 说明超大请求会被拒绝，而非截断。比较时应记录引擎、硬件、推理模式、置信度定义和输入限制；这些是发布者说明，不是本项目已测试的部署。 Span-02 运行库与榜单配置 · Lychee 模型卡限制

同一检查点的输入支持与校准方法也可能因模态而异。Liquid d1-omni-600M 的单次请求只能选择图像或音频；语音限 30 秒，图像请求中的文本限 896 个 token。拟合温度仅用于文本，不用于图像或音频。该版本使用自定义推理代码与 LFM Open License v1.0，应单独检查许可，不能从基础模型或其他 d1 版本推断。 Liquid d1-omni-600M：限制与校准 · LFM Open License v1.0

开放 RLCD 实现是否复现了 Jev 的训练？
